# SoundFont Synthesizer & QSPI Flash (XIP) в PurrMidi

## 1. Обзор

PurrMidi содержит синтезатор SoundFont2 (SF2) на базе адаптации [TinySoundFont](https://github.com/schellingb/TinySoundFont).

**Банк SoundFont хранится только во внешней QSPI Flash** и читается синтезатором на месте — через память-отображённое окно
(Memory-Mapped / XIP, `0x90000000...`). Копии сэмплов в ОЗУ нет, потокового чтения и кэша нет.
**SD-карта используется только при запуске**, чтобы обновить банк во флеше: если на карте лежит новый или изменённый файл
`0:/SNDFNT.SF2`, загрузчик перепишет им флеш, после чего SD-карта отключается. Во время игры SD-карта не нужна и не используется;
без SD-карты прибор работает с банком, уже записанным во флеш.

```text
        старт                                              игра
SD: 0:/SNDFNT.SF2 ──(новый/изменён?)──► QSPI Flash ══XIP 0x90000000══► TinySoundFont ──► SAI/DMA
   (читается только здесь, read-only)    (банк до ~8 МБ)             (PCM читается на месте)
```

На ПК (хостовые тесты, Windows-приложение) тот же интерфейс `sf2_loader.h` реализован в `Platform/host/sf2_loader_host.cpp`:
роль «флеша» играет область ОЗУ, в которую файл банка читается целиком. Синтезатор в обоих случаях работает одинаково — читает PCM по указателю.

Выбор синтезатора выполняется сообщением MIDI Program Change `7` и выше — по одной программе на каждый пресет банка (или кнопкой User Key K1 на плате, которая обходит список по кругу).

## 2. Выбор инструмента

| Program Change | Движок | Описание |
|---|---|---|
| `0` | **E-Piano** | Полифоническое FM-электропиано (по умолчанию) |
| `1` | **Pluck** | Физическое моделирование струны (Карплус — Стронг) |
| `2` | **Lead** | Полифонический субтрактивный синтезатор лидов |
| `3` | **Organ** | Тонколесный орган (bfreeOrgan2) |
| `4` | **Dulcimer** | Цимбалы на модальном резонаторе Elements |
| `5` | **Flute** | Физическая модель флейты |
| `6` | **Saxophone** | Физическая модель саксофона |
| `7…` | **SoundFont** | Синтезатор SoundFont2 (TinySoundFont); `7` — первый пресет банка, `8` — второй и т. д. |

SoundFont стоит в конце списка, потому что число его программ зависит от банка. Порядок пресетов — порядок банка (по номеру банка и программы), в список входят все пресеты, включая ударные. На дисплее пишется «SF:имя пресета» (имя из банка, пробелы по краям срезаются, влезает до 17 символов). Если пресетов больше, чем номеров Program Change (`0…126`), остальные доступны циклом `127`.

Номера за пределами списка заворачиваются по модулю числа программ (`program % (7 + число пресетов)`). Сообщение Program Change `127` циклически переключает на следующую доступную программу. Если во флеше нет валидного банка (и SD-карта с файлом при запуске не вставлена) или банк повреждён, SoundFont и все его пресеты помечаются недоступными и пропускаются при переключении. Выбранный пресет сохраняется при `Panic` и при переключении на другой движок и обратно; смена пресета при уже активном SoundFont не обрывает звучащие ноты.

API: `SoundFontSynth_GetPresetCount()`, `SoundFontSynth_GetPresetName()`, `SoundFontSynth_SelectPreset()`, `SoundFontSynth_GetPreset()`; на уровне диспетчера — `SynthEngine_GetProgramCount()`, `SynthEngine_GetProgram()`, `SynthEngine_SelectProgram()`, `SynthEngine_GetProgramName()`.

### Защита от перегрузки

Каждое событие рендера сначала сбрасывает денормальные числа в ноль (`synth::EnableFlushToZero()`, бит FPSCR.FZ): затухающие хвосты огибающих и фильтров иначе резко замедляют FPU. Кроме того, если блок занял больше 75% бюджета (`SF2_SHED_THRESHOLD_PCT`), `tsf_shed_releasing_voices()` ускоренно (за ~10 мс) гасит до 4 (`SF2_SHED_VOICES_PER_BLOCK`) уже отпущенных голосов с самыми тихими хвостами; звучащие ноты не затрагиваются. Число погашенных голосов выводится в строке `[SF2]` как `shed_voices`.

## 3. QSPI Flash и XIP (Memory-Mapped)

В основном режиме банк `SNDFNT.SF2` (размером до **8 384 512 байт** = 8 МБ − 4 КБ заголовок) хранится во внешней микросхеме QSPI Flash (Winbond W25Q64) и читается синтезатором напрямую по адресам `0x90000000...` (Memory-Mapped, XIP).

### 3.1. Процесс старта и обновления (`SoundFontSynth_InitSF2` → `SF2Loader_Ensure`)

1. **Инициализация QSPI**: программный сброс флеш-памяти, чтение JEDEC ID (`0xEF 0x40 0x17`), установка бита Quad Enable (QE).
2. **Проверка SD-карты** (единственное место, где используется SD): при старте SD монтируется только для чтения и проверяется наличие файла `0:/SNDFNT.SF2`; после обновления (или если файла нет) SD-карта сразу отключается (`SDStorage_Unmount()`).
   - Заголовок флеш-памяти сравнивается с файлом на SD-карте (размер, метка времени файла, при расхождениях — CRC32).
   - Если банк во флеш-памяти совпадает с файлом на SD-карте (или SD-карта отсутствует, а во флеше валидный заголовок) — запись **не выполняется**, старт происходит мгновенно.
3. **Запись / Обновление банка**:
   - При обнаружении нового или изменённого файла: стирается заголовок флеш-памяти → стираются блоки данных (64 КБ / 4 КБ сектора) → выполняется запись страницами по 256 байт → вычисляется и проверяется CRC32 всего банка через XIP → записывается заголовок (коммит).
   - Потеря питания в процессе записи безопасна: заголовок не закоммичен, поэтому при следующем старте с SD-картой запись повторится автоматически.
   - Прогресс отображается на TFT-дисплее и выводится в UART (`[SF2] ...`). Полная запись 8 МБ занимает 30–60 секунд.
4. **Перевод в Memory-Mapped**: QSPI переводится в режим прямого адресации `0x90000000`, открывается кэшируемое MPU-окно, и TinySoundFont разбирает метаданные (пресеты, генераторы, зоны) из адресов XIP. Блок PCM (`smpl`) TinySoundFont не копирует: указатель на него передаётся функцией `tsf_set_smpl_pcm16()`, голоса читают отсчёты прямо из флеша (за пределами банка читается тишина).

**Защита XIP.** Индексные операции QSPI (`QSPIFlash_Read/EraseSector/ProgramPage`) сами выходят из Memory-Mapped режима и закрывают MPU-окно `0x90000000`. Драйвер сбрасывает признак `QSPIFlash_IsMapped()` *до* закрытия окна и устанавливает его *после* открытия (рендер в PendSV может вытеснить `main` в любой точке, но не наоборот), а движок SoundFont перед каждым блоком вызывает `SF2Loader_BankReadable()` и при закрытом окне отдаёт тишину вместо чтения банка (иначе MemManage). После индексных операций окно нужно открыть заново (`QSPIFlash_MemoryMap()`); голоса при этом не теряются, а лишь стоят на месте.

**Ограничение:** загрузчик выполняется один раз при старте, до запуска аудио и USB. Во время игры банк обновить нельзя — для этого выключите прибор, вставьте SD-карту с новым `SNDFNT.SF2` и включите снова.

### 3.2. Требование D-Cache для XIP

Без D-Cache каждое чтение `int16_t` из XIP порождает отдельную транзакцию QSPI (сотни наносекунд), что при нескольких голосах приводит к задержкам аудиотракта.

С включённым D-Cache строка 32 байта (16 отсчётов) подтягивается из флеш-памяти за одну транзакцию:
* Функция `XipMpu_Config()` настраивает MPU-регион для адресов `0x90000000...0x907FFFFF` (8 МБ, Normal, Read-Only, Write-Through, Outer/Inner Cacheable).
* Функция `SCB_EnableDCache()` включает D-Cache.
* DMA-буферы (SAI1, SDMMC1) лежат только в D2 SRAM (Normal Non-cacheable); AXI SRAM (арена голосов и куча TinySoundFont) кэшируется write-back. XIP-окно QSPI кэшируется write-through (только чтение).

### 3.3. Настройка CubeMX для QUADSPI

**Connectivity → QUADSPI**

| Параметр | Значение |
|---|---|
| Mode | **Bank1 with Quad SPI Lines** |
| Clock Prescaler | **2** (80 МГц) или **1** (120 МГц, предел W25Q64 — 133 МГц) |
| FIFO Threshold | 1 |
| Sample Shifting | **Half Cycle Shift** |
| Flash Size | **22** (в коде `hqspi.Init.FlashSize = 22`: размер = 2^(22+1) = 8 МБ) |
| Chip Select High Time | **5 Cycles** |
| Clock Mode | Low |
| Flash ID | 1 |
| Dual Flash | Disabled |

**Пины** (платы WeAct STM32H743):
* `PB2` — QUADSPI_CLK
* `PB6` — QUADSPI_BK1_NCS
* `PD11` — QUADSPI_BK1_IO0
* `PD12` — QUADSPI_BK1_IO1
* `PE2` — QUADSPI_BK1_IO2
* `PD13` — QUADSPI_BK1_IO3 *(обратите внимание: именно PD13, а не PA1!)*

Скорость GPIO Speed для всех 6 выводов: **Very High**.

## 4. Память и поток событий

* **Использование кучи**: TinySoundFont требует порядка 170 КБ кучи для разбора таблиц пресетов банка размером ~27 МБ.
  На STM32 куча Newlib расположена в секции `.axi_heap` в AXI SRAM (размером 320 КБ, симбол `_Axi_Heap_Size` в `STM32H743xx_FLASH.ld`).
* **Потокобезопасность MIDI**: Сообщения NoteOn, NoteOff, ControlChange и ProgramChange передаются из основного цикла в аудиоконтекст через lock-free SPSC FIFO и применяются в начале рендеринга аудиоблока `SoundFontSynth_FillStereoBuffer()`.

## 5. Тестирование и диагностика

* **Сторожевой таймер**: на время обновления банка действует загрузочный таймаут IWDG1 (~8 с); `on_progress()` загрузчика вызывает `Watchdog_Kick()` на каждом шаге (стирание, запись, проверка). Рабочий таймаут (~1,5 с) включается после запуска аудио.
* **UART-логирование**: При старте и записи выводится подробная диагностика (`[SF2] ...`, `[QSPI] ...`, при ошибке SD — `[SD] ...`).
* **Статистика при игре** (`SoundFontSynth_ReportStats()`, строка `[SF2] 1s: ...` раз в секунду, пока играют ноты):
  время рендера avg/max и число блоков дольше бюджета, активные голоса (лимит 32), `want/started/short` (голоса,
  которых нотам не хватило: украдены у затухающих нот - щелчок - или потеряны), пик микса в долях полной шкалы
  (`FS`) и число отсчётов выше 1.0 FS, потерянные MIDI-события. Строка `[AUDIO]` из `main.c` показывает общее время
  времени рендера блока (в PendSV), `shed` - сколько блоков заменено тишиной из-за перегрузки, `late` - сколько раз рендер не успел к сроку.
* **Мягкий лимитер** (`SF2_SOFT_LIMITER`, по умолчанию 1): TinySoundFont суммирует голоса без запаса по уровню и жёстко
  обрезает на полной шкале, поэтому громкие аккорды (3-6 нот) звучат искажённо. Лимитер не меняет сигнал ниже порога
  `SF2_LIMITER_KNEE` (0.6 FS) и плавно прижимает пики к `SF2_LIMITER_CEILING` (0.98 FS). `SF2_GLOBAL_GAIN_DB` -
  общая громкость банка в дБ (по умолчанию 0). Все три значения переопределяются через `-D`.
* **Хостовые юнит-тесты**:
  * `test_sf2_loader_core`: эмуляция NOR-флеш, логика пропуска записи, битовые флаги, сбои питания, CRC32.
  * `test_sf2_xip_host`: TinySoundFont поверх банка «в памяти» (имитация окна XIP), в том числе хеш выходного сигнала.
  * `test_soundfont_host`: движок SoundFont на реальном банке: рендер без подкачки, отсутствующий/испорченный/обрезанный банк, удерживаемые ноты без «дыр», события во время рендеринга из другого потока.

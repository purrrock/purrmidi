# Проверка прошивки на плате

Автотесты проверяют логику на хосте, а прошивку целиком (память, DMA, USB, QSPI, время рендера) можно проверить только на
плате. Этот чеклист — минимум перед тем, как считать сборку годной. Отмечайте пункты галочками прямо в копии файла.

**Что понадобится:** ST-Link (SWD); USB-UART адаптер на `PB10` (TX платы) и `PB11` (RX платы), 115200 8N1 (см.
`PINOUT.md`, `USB-UART adapter.md`); USB MIDI-клавиатура; по возможности педаль сустейна; SD-карта с `SNDFNT.SF2`.

## 0. Сборка и прошивка

Release (то, что работает на приборе) берётся из артефактов CI (`purrmidi.elf`, `.bin`, `.hex`) или собирается локально:

```
cmake --preset Release
cmake --build --preset Release
bash tools/check_firmware_size.sh build/Release/purrmidi.elf
```

Прошивка через OpenOCD (скрипты — как в `tools/openocd-run.cmd`):

```
openocd -f interface/stlink-dap.cfg -f target/stm32h7x.cfg -c "program build/Release/purrmidi.elf verify reset exit"
```

или STM32CubeProgrammer: `purrmidi.bin` по адресу `0x08000000`.

Для сравнения «до/после» держите под рукой Release предыдущей версии (артефакт CI прошлого коммита): если звук вызывает
сомнение, прошейте её и сравните на слух одни и те же ноты.

## 1. Загрузка

Откройте терминал на UART и перезапустите плату.

- [X] Есть строка `[SYS] build: optimized` (а не `NOT OPTIMIZED`: это Debug).
- [X] Есть `[SYS] SYSCLK=... audio budget 2666 us per 128 frames`.
- [X] SoundFont: `[SF2] SoundFont ready` (при новом `SNDFNT.SF2` на SD сначала идёт запись во флеш, 30–60 секунд).
- [X] Нет строки `[MEM] WARNING: heap ...` (куча SoundFont по-прежнему 320 КБ, у неё лишь сменился адрес).
- [X] В Release **нет** периодических строк `[AUDIO] ...`: диагностика там выключена, это нормально.
- [X] Дисплей показывает инструмент и громкость, USB-клавиатура определяется.

## 2. Движки и общая арена голосов

Арена (72 КБ) общая для Pluck (1), Lead (2) и Violin (4): при каждом переключении она заново обнуляется. Это главное, что
меняло уменьшение арены, поэтому проверяйте именно переходы.

- [X] Пройдите по кругу все программы кнопкой `K1` (`PC13`) или Program Change `127`: 0 E-Piano, 1 Pluck, 2 Lead, 3 Organ,
  4 Violin, затем пресеты SoundFont (5…). Не меньше 10 полных кругов. В UART на каждое переключение строка
  `[PC] ... program N -> <имя>`.
- [X] Переходы между движками арены в разном порядке (1→4→2→1 и обратно через Program Change `1`, `4`, `2`): звук чистый, нет
  тишины, щелчков, зависаний.
- [-] На каждом движке сыграйте 8 нот одновременно и держите до затухания (максимальная полифония): нет хрипов и пропусков.
- [X] Быстрое переключение: 20–30 нажатий `K1` подряд с зажатыми нотами. Прибор не зависает, дисплей не «зависает» на старом
  имени, после остановки играет текущий инструмент.
- [X] Звук на слух соответствует прежней версии (тембр, громкость, затухание).

## 3. Нагрузка на аудио-тракт (Release с диагностикой)

В обычном Release статистика выключена. Чтобы измерить время рендера, соберите отдельный Release с включённой диагностикой
(оба флага нужны: `main.c` на C, `soundfont_synth.cpp` на C++):

```
cmake --preset Release -B build/Release-diag -DCMAKE_C_FLAGS="-DAUDIO_DIAG_UART=1" -DCMAKE_CXX_FLAGS="-DAUDIO_DIAG_UART=1 -DSF2_DIAG_STATS=1"
cmake --build build/Release-diag
```

Прошейте `build/Release-diag/purrmidi.elf`. Строки `[AUDIO] <движок>: fill last=… max=… us (NN% of 2666 us) >80%: … >100%: …
shed=… late=…` появляются при росте максимума или нарушении порогов, статистика ведётся отдельно для каждого движка.

- [-] Плотные аккорды с педалью на каждом движке и на SoundFont-пресетах (особенно роялем): `max` заметно меньше 100 %
  (ориентир — ниже 80 %), `>100%: 0`, `shed=0`, `late=0`.
- [-] Если есть `>100%` или `late`, запишите движок, пресет и аккорд: это нужно для разбора. Строка `[AUDIO] RENDER OVERRUN`
  означает, что блок не уложился в бюджет.

После измерений прошейте обычный Release.

## 4. Перезапуск из Error_Handler

`Error_Handler()` теперь печатает отчёт, ждёт около секунды и перезапускает прибор (раньше он зацикливался до сброса по
watchdog, а до его запуска не перезапускался совсем).

- [X] Временно добавьте `Error_Handler();` сразу после строки с `printf("[SYS] SYSCLK=...` в `Core/Src/main.c`, соберите, прошейте.
  Ожидание: в UART повторяется загрузка и после неё `*** Error_Handler() called, LR=0x...`, перезапуск примерно раз в 1–2
  секунды, без зависаний.
- [X] Верните файл (`git checkout Core/Src/main.c`), пересоберите, прошейте.

Для отладки по SWD соберите с `-DPURRMIDI_FAULT_HALT=1`: тогда `Error_Handler()` и обработчики сбоев остановятся в
бесконечном цикле вместо перезапуска.

## 5. Регрессия: то, чего не покрывают тесты

- [X] Отключение USB-клавиатуры при зажатых нотах: звук не залипает, после повторного подключения всё играет.
- [X] Горячее подключение клавиатуры после загрузки.
- [X] Холодный запуск (по питанию) и перезапуск кнопкой сброса: звук с первой ноты, нет щелчка при старте.
- [X] Обновление банка с SD: положите изменённый `SNDFNT.SF2`, перезапустите, дождитесь `[SF2] SoundFont ready`, проверьте
  несколько пресетов.
- [X] Прибор без SD-карты и без банка: запускается, SoundFont-программа сообщает об ошибке, остальные движки работают.

## 6. Плотные аккорды: Organ и SoundFont (после правок AutoGain и регулятора нагрузки)

Что проверялось раньше: Organ хрипел на шести и более клавишах (причина измерена: усиление ×3,5 уводило пик за колено
ограничителя, нагрузка CPU при этом всего 17%), SoundFont хрипел на пяти и более (блок вылетал за бюджет 2666 мкс,
в логе `RENDER OVERRUN`, `shed`, `late`). Обе проблемы поправлены, нужна проверка на плате. Прошивайте Release.

**Organ** (программа 3, обычный Release):

- [X] Аккорд из 6, 8 и 10 клавиш (удерживать 3–5 секунд): звук чистый, без хрипа и дребезга на вершинах.
- [X] На одной-двух нотах громкость и тембр прежние (усиление ×3,5, регулятор не вмешивается).
- [X] На плотных аккордах громкость перестаёт расти (уровень около −11 дБFS), уже звучащие ноты слегка «приседают» при добавлении
  новых: это нормально. Подозрительно только заметное «дыхание» громкости на устойчивом аккорде.
- [X] После отпускания плотного аккорда следующая одиночная нота сначала чуть тише и за долю секунды выравнивается: это
  возврат усиления (постоянная времени 0,25 с). Если мешает, `ORGAN_AGC_RELEASE` в `organ_synth.cpp` можно уменьшить (0,1–0,15).

**SoundFont** (Release с диагностикой, команда из раздела 3; нужны оба флага, иначе строк `[SF2]` не будет):

- [ ] Аккорды из 4, 5, 6, 8 клавиш, затем то же с педалью: хрипа нет, `RENDER OVERRUN` не появляется,
  `>100%: 0`, `late=0`.
- [ ] Аккорд «раскатывается» не слышимо (при высокой нагрузке Note On растягиваются на несколько блоков по 2,7 мс). Если на
  слух рояльный аккорд стал «размазанным», пришлите строки `[SF2]`: порог `SF2_EVENT_BUDGET_PCT` (85) подберём.
- [ ] Звучащие ноты при плотной игре с педалью не обрываются на слух. Если слышно, что ноты гаснут раньше времени,
  смотрите поле `shed_sounding` в строке `[SF2]` (порог `SF2_SHED_SOUNDING_PCT`, 90).
- [ ] **Скопируйте строки `[SF2] 1s: ...` из лога** при любых проблемах и один раз при нормальной игре аккордами: в них есть
  число голосов (`voices max=`), регионов на ноту (`regions want=`, `max/note=`) и новые поля `events max=… us`
  (время обработки Note On за блок), `deferred`, `shed_sounding`. По ним видно, куда уходит время: в события или в рендер.
  Строки печатаются раз в секунду и только при проблемах (превышение бюджета, нехватка голосов, перегрузка микса, отложенные
  события, погашенные звучащие ноты).

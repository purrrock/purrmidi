# SoundFont, QSPI Flash (XIP) и SD-карта

Синтезатор SoundFont2 в PurrMidi основан на [TinySoundFont](https://github.com/schellingb/TinySoundFont). Выбор пресетов и
правила Program Change — в [ENGINES.md](ENGINES.md), карта памяти и MPU — в [ARCHITECTURE.md](ARCHITECTURE.md).

## Как это работает

Банк хранится **только во внешней QSPI Flash** (W25Q64, 8 МБ) и читается синтезатором на месте через memory-mapped окно
(XIP, `0x90000000…`): копии сэмплов в ОЗУ нет. **SD-карта используется только при запуске**, чтобы обновить банк: если на карте
лежит новый или изменённый `0:/SNDFNT.SF2`, загрузчик перепишет им флеш, после чего SD отключается. Во время игры карта не нужна;
без карты прибор работает с банком, уже записанным во флеш.

```text
        старт                                              игра
SD: 0:/SNDFNT.SF2 ──(новый/изменён?)──► QSPI Flash ══XIP 0x90000000══► TinySoundFont ──► SAI/DMA
   (читается только здесь, read-only)    (банк до 8 МБ)             (PCM читается на месте)
```

На ПК (хостовые тесты, Windows-приложение) тот же интерфейс `sf2_loader.h` реализован в `Platform/host/sf2_loader_host.cpp`:
роль флеша играет область ОЗУ, куда файл банка читается целиком.

## Обновление банка

1. Положите файл в корень microSD (FAT32) под именем `SNDFNT.SF2`. Размер не более **8 384 512 байт** (8 МБ минус 4 КБ заголовка).
   Уменьшить банк можно скриптом `SoundFonts/sf2_shrink.py` или программой Polyphone.
2. Вставьте карту и включите прибор. Банк записывается за 30–60 секунд, прогресс виден на дисплее и в UART.
3. После `[SF2] SoundFont ready` карту можно вынуть.

При старте загрузчик сравнивает заголовок во флеше с файлом на карте (размер, штамп времени, при расхождении CRC32):

* совпадает, или карты нет, а во флеше валидный банк — запись не выполняется, старт мгновенный;
* банк на карте новый или изменённый — стирание и запись заново;
* банка нет нигде или он повреждён — SoundFont и его пресеты недоступны и пропускаются при переключении, остальные движки работают.

Потеря питания во время записи безопасна: заголовок записывается последним (коммит), поэтому при следующем старте с картой запись
повторится сама. Во время игры банк обновить нельзя: выключите прибор, вставьте карту, включите.

### Процесс записи (`SoundFontSynth_InitSF2` → `SF2Loader_Ensure`)

1. Инициализация QSPI: сброс флеша, чтение JEDEC ID (`0xEF 0x40 0x17`), включение Quad Enable.
2. Монтирование SD только для чтения, сравнение с заголовком; после обновления (или если файла нет) `SDStorage_Unmount()`.
3. Запись: стирание заголовка → стирание блоков (64 КБ / 4 КБ) → запись страницами по 256 байт → CRC32 всего банка через XIP →
   запись заголовка. Во время обновления действует загрузочный таймаут IWDG1 (~8 с), загрузчик вызывает `Watchdog_Kick()`
   на каждом шаге; рабочий таймаут (~1,5 с) включается после запуска аудио.
4. Перевод QSPI в memory-mapped режим, открытие кэшируемого MPU-окна, разбор метаданных (пресеты, генераторы, зоны) из XIP.
   Блок PCM TinySoundFont не копирует: указатель передаётся через `tsf_set_smpl_pcm16()`, голоса читают отсчёты прямо из флеша.

Контракт XIP (индексные операции закрывают окно, `SF2Loader_BankReadable()`, тишина вместо MemManage) описан в
[ARCHITECTURE.md](ARCHITECTURE.md#dma-d-cache-и-память-stm32). D-Cache для региона `0x90000000…0x907FFFFF` обязателен: без него
каждое чтение `int16_t` из XIP порождает отдельную транзакцию QSPI, и при нескольких голосах аудиотракт не успевает.

## Настройка CubeMX

Выводы QUADSPI и SDMMC1 — в [HARDWARE.md](HARDWARE.md).

**QUADSPI**

| Параметр | Значение |
|---|---|
| Mode | Bank1 with Quad SPI Lines |
| Clock Prescaler | 2 (80 МГц) или 1 (120 МГц; предел W25Q64 — 133 МГц) |
| FIFO Threshold | 1 |
| Sample Shifting | Half Cycle Shift |
| Flash Size | 22 (2^(22+1) = 8 МБ; в коде `hqspi.Init.FlashSize = 22`) |
| Chip Select High Time | 5 Cycles |
| Clock Mode | Low |
| Flash ID | 1 |
| Dual Flash | Disabled |

Подтяжки не нужны, DMA и прерывания QUADSPI не используются. GPIO Speed шести выводов — Very High.

**SDMMC1 и FatFs**

1. Connectivity → SDMMC1: `SD 4 bits Wide bus`, Clock Edge — Rising, Clock Power Save и Hardware Flow Control — Disable.
2. Источник тактирования SDMMC — PLL1Q (192 МГц), Clock divide factor `4` → SDMMC_CK 24 МГц (`192 / (2·4)`).
3. GPIO: скорость Very High, подтяжки вверх на D0–D3 и CMD, на CLK без подтяжки.
4. Middleware → FATFS: `User-defined` (драйвер — `Platform/sd/sd_storage.c`, только чтение; вызовы `MX_SDMMC1_SD_Init` и
   `MX_FATFS_Init` отключены), `USE_LFN` — Enabled with static working buffer, `MAX_SS`/`MIN_SS` 512, `USE_FASTSEEK` — Enabled,
   `FS_READONLY` 1, `FS_LOCK` 0, `USE_MKFS` 0.

Режим «SD Card» в CubeMX не используется: сгенерированная инициализация при отсутствии карты вызывает `Error_Handler()` и вешает
прибор, а IDMA SDMMC1 не видит DTCM, поэтому нужны обходы (bounce-буфер, проверки выравнивания и кэша), которые уже есть в
`sd_storage.c`.

## Защита от перегрузки

Каждый блок рендера начинается со сброса денормалей в ноль (`synth::EnableFlushToZero()`): иначе затухающие хвосты резко
замедляют FPU. Старт голоса TinySoundFont дорог, и плотный аккорд запускает десятки голосов в одном блоке (бюджет 2,67 мс).
Для этого есть три механизма (`Engine/synth/synth_common.h`, `soundfont_synth.cpp`):

* **Гашение отпущенных голосов.** Если блок занял больше 75% бюджета (`SF2_SHED_THRESHOLD_PCT`), `tsf_shed_releasing_voices()`
  за ~10 мс гасит до 4 (`SF2_SHED_VOICES_PER_BLOCK`) отпущенных голосов с самыми тихими хвостами.
* **Откладывание Note On (`synth::LoadGovernor`).** Перед каждым Note On считается прогноз: потраченное на события в блоке плюс
  рендер всех голосов по измеренной цене голоса. Если он выше `SF2_EVENT_BUDGET_PCT` (85%), этот Note On и все следующие ждут
  следующего блока. Порядок сохраняется, один Note On за блок применяется всегда. Цена: при высокой нагрузке аккорд «раскатывается»
  на несколько блоков по 2,7 мс.
* **Гашение звучащих нот.** Если рендер выше `SF2_SHED_SOUNDING_PCT` (90%) два блока подряд, а отпущенных голосов нет,
  `tsf_shed_sounding_voices()` за ~10 мс гасит ноту целиком (все регионы): сначала удерживаемые только педалью, затем самую
  тихую; ноты в атаке не трогаются. Между гашениями пауза 4 блока, при перегрузке выше 110% гасятся две ноты за раз.

**Мягкий лимитер** (`SF2_SOFT_LIMITER`, по умолчанию 1): TinySoundFont суммирует голоса без запаса и жёстко обрезает на полной
шкале. Лимитер не меняет сигнал ниже `SF2_LIMITER_KNEE` (0,6 FS) и прижимает пики к `SF2_LIMITER_CEILING` (0,98 FS).
`SF2_GLOBAL_GAIN_DB` — общая громкость банка в дБ (по умолчанию 0). Все значения переопределяются через `-D`.

## Диагностика

Все сообщения идут в UART (`[SF2]`, `[QSPI]`, `[SD]`).

**Статистика игры** — строка `[SF2] 1s: ...` раз в секунду, только при проблемах (превышение бюджета, нехватка голосов, перегрузка
микса, отложенные события, погашенные ноты). Для неё нужна сборка с `-DAUDIO_DIAG_UART=1 -DSF2_DIAG_STATS=1` (см.
[ARCHITECTURE.md](ARCHITECTURE.md#диагностические-флаги-сборки)). Поля: время рендера avg/max и число блоков дольше бюджета; активные голоса (`voices`);
`want/started/short` (сколько голосов нотам не хватило); пик микса (`FS`) и число отсчётов выше 1,0 FS; потерянные MIDI-события;
`events max` (время обработки Note On за блок), `deferred`, `shed_voices`, `shed_sounding`. Строка `[AUDIO]` из `main.c` показывает
общее время рендера блока: `shed` — блоков, заменённых тишиной из-за перегрузки, `late` — сколько раз рендер не успел к сроку.

**SD не монтируется / файл не открывается:**

| Строка в логе | Что означает |
|---|---|
| `SD mount failed: INIT`, `hsd.ErrorCode=0x...` | `HAL_SD_Init` не поднял карту: контакт, питание, тактирование, несовместимая карта. Код расшифровывается по маске `HAL_SD_ERROR_*` |
| `SD mount failed: LINK` | `FATFS_LinkDriver` не удался: в проекте остался вызов `MX_FATFS_Init` или `_VOLUMES` ≠ 1 |
| `SD mount failed: MOUNT`, `f_mount=13` | Карта читается, но FatFs не нашёл файловую систему (`FR_NO_FILESYSTEM`): проверьте разметку и формат |
| `SD mount failed: MOUNT`, `f_mount=1`, `first read failure: stage=...` | `FR_DISK_ERR`. `stage=1` — карта не вернулась в TRANSFER, `2` — отказ `HAL_SD_ReadBlocks_DMA`, `3` — таймаут/ошибка DMA |
| `f_open(...) failed: FRESULT=4` | Файла с таким именем в корне нет. Следом печатается `[SD] root directory`: частый случай — Windows скрыл расширение, и файл называется `SNDFNT.SF2.sf2` |

Датчик карты (`SD_DETECT`, PD4) не используется: наличие карты определяет `HAL_SD_Init`.

**QSPI:** если флеш не определяется (JEDEC ID `00 00 00` или `FF FF FF`), проверьте, что IO3 назначен на PD13, а не на PA1
(см. [HARDWARE.md](HARDWARE.md#qspi-flash-банк-soundfont-xip)). Предупреждение `hqspi.Init.FlashSize=... expected 22` означает
неверный Flash Size в CubeMX.

# Сборка и запуск PurrMidi на Windows (Host App)

Данный документ описывает процесс сборки и запуска хостового приложения `purrmidi_win.exe` под Windows. Приложение объединяет MIDI-монитор и синтезаторы проекта (звуковые движки: `epiano`, `pluck`, `lead`/`sine`, `organ`, `violin` и `soundfont` — последний с отдельной программой на каждый пресет SF2; переключаются во время работы MIDI-сообщением Program Change), позволяя отлаживать и настраивать звучание на ПК без прошивки микроконтроллера STM32.

---

## 1. Необходимое программное обеспечение

Для сборки хостового приложения на ПК понадобятся:
* **VS Code** с расширениями:
  * `ms-vscode.cmake-tools` (CMake Tools)
  * `ms-vscode.cpptools` (C/C++)
* **Инструменты компиляции (один из вариантов):**
  * **MSVC**: Visual Studio Build Tools 2022 (компонент «Разработка классических приложений на C++» / «Desktop development with C++»).
  * **MinGW-w64**: MSYS2 или готовый тулчейн MinGW-w64 (GCC 11+).
* **CMake** версии 3.22 или выше.
* **Ninja** (системы сборки).

---

## 2. Получение исходников

Подмодулей Git в проекте нет, достаточно обычного клонирования:

```bash
git clone https://github.com/purrrock/purrmidi
```

Нужная часть DaisySP (`Oscillator`, `Svf`, `Adsr`) лежит в `Middlewares/Third_Party/DaisySP_lite/`.

## 3. Сборка из командной строки (Presets)

Проект использует `CMakePresets.json`.

### Вариант А: Сборка с MSVC (Visual Studio Build Tools)

```cmd
cmake --preset win-msvc-release
cmake --build --preset win-msvc-release
```

Исполняемый файл будет сохранен в: `build/win-msvc-release/Platform/windows/purrmidi_win.exe`.

### Вариант Б: Кросс-компиляция или сборка с MinGW-w64

```bash
cmake --preset win-mingw-release
cmake --build --preset win-mingw-release
```

Исполняемый файл будет сохранен в: `build/win-mingw-release/Platform/windows/purrmidi_win.exe`.

### Выбор синтезатора

Все синтезаторы всегда входят в сборку, а активный выбирается во время работы сообщением MIDI Program Change (как и в прошивке STM32):

При запуске в режиме `--play` приложение печатает `Synth engine: ...`, а при каждой смене — `[PC] program N -> synth engine: ...`.

### Прогон тестов (Host Tests)

```bash
cmake --preset host-tests
cmake --build --preset host-tests
ctest --test-dir build/host-tests --output-on-failure
```

Тесты каждого синтезатора  проверяют сами движки; `test_queue_dispatch` — цепочку «очередь → диспетчер → синтезатор», а `test_synth_switch` — переключение синтезаторов по Program Change (по умолчанию E-Piano, заворачивание номеров, обрыв старого звука, смена при работающем аудио-потоке).

## 4. Сборка в VS Code

1. Скопируйте шаблоны настроек из `docs/vscode/` в папку `.vscode/`:
   ```cmd
   mkdir .vscode
   copy docs\vscode\* .vscode\
   ```
2. Откройте папку проекта в VS Code.
3. Нажмите на панель выбора конфигурации CMake (в строке состояния снизу или через `Ctrl+Shift+P` -> `CMake: Select Configure Preset`).
4. Для хостовой сборки выберите пресет **`win-msvc-release`** (или `win-msvc-debug` / `win-mingw-release`).
5. Для сборки прошивки STM32 выберите пресет **`Release`** или **`Debug`**.
6. Нажмите `F7` или кнопку **Build** в строке состояния.

## 5. Использование `purrmidi_win.exe`

### 1) Просмотр доступных устройств (`--list`)

```cmd
purrmidi_win.exe --list
```

Пример вывода:
```text
--- MIDI Input Ports ---
  [0] USB MIDI Keyboard
--- Audio Output Devices ---
  [0] Speakers (Realtek High Definition Audio) (Default)
```

### 2) Запуск MIDI-монитора (`--monitor`)

Печать всех поступающих MIDI-сообщений без вывода звука:

```cmd
purrmidi_win.exe --monitor --midi-port 0
```

Дополнительно отображать служебные Realtime-сообщения (Clock `0xF8`, ActiveSensing `0xFE`):

```cmd
purrmidi_win.exe --monitor --midi-port 0 --show-realtime
```

### 3) Запуск синтезатора (`--play`)

Игра на клавиатуре через синтезатор, выбранный при сборке:

```cmd
purrmidi_win.exe --play --midi-port 0
```

Запись выходного аудиопотока в WAV-файл:

```cmd
purrmidi_win.exe --play --midi-port 0 --wav output.wav --wav-seconds 120
```

Настройка размера аудиобуфера и гейна:

```cmd
purrmidi_win.exe --play --midi-port 0 --buffer-frames 128 --gain 0.9
```

Остановка работы осуществляется комбинацией `Ctrl+C`.

## 6. Виртуальная MIDI-клавиатура

В хостовое приложение `purrmidi_win.exe` встроена виртуальная MIDI-клавиатура, позволяющая играть и отлаживать синтезаторы с помощью компьютерной клавиатуры без подключения физической MIDI-клавиатуры.

### Включение и параметры командной строки

Виртуальная клавиатура активна по умолчанию при запуске `purrmidi_win.exe` в режиме `--play` или `--monitor`.

Настройки ввода с клавиатуры через CLI:
* `--octave N` — базовая октава (от `0` до `8`, по умолчанию `4`, при которой клавиша `Z` соответствует ноте C4 / MIDI 60).
* `--velocity V` — громкость нажатия для событий `Note On` (от `1` до `127`, по умолчанию `100`).

Пример запуска с базовой октавой 3 и velocity 120:

```cmd
purrmidi_win.exe --play --midi-port 0 --octave 3 --velocity 120
```

### Таблица соответствия клавиш нотам

### Особенности работы и защита от зависших нот

1. **Многоголосие и аккорды:** Поддерживается одновременное удержание нескольких клавиш для воспроизведения аккордов.
2. **Игнорирование автоповторов:** Автоматические повторные нажатия (Key Down auto-repeat) удерживаемых клавиш от операционной системы отфильтровываются и не вызывают повторных `Note On`.
3. **Корректность Note Off:** При отпускании клавиши отправляется `Note Off` именно для той MIDI-ноты, которая была зафиксирована в момент её нажатия (даже если во время удержания клавиши базовая октава была изменена).
4. **Сброс при потере фокуса:** При переключении фокуса с окна консоли (например, по Alt+Tab) виртуальная клавиатура автоматически отправляет `Note Off` для всех удерживаемых в этот момент нот, предотвращая их «зависание».

## 7. Известные ограничения и особенности

**Задержка аудио (Latency):** Аудиовывод под Windows осуществляется через подсистему WASAPI/miniaudio. Задержка зависит от размера буфера (`--buffer-frames`) и аудионастроек ОС, в то время как на STM32 вывод осуществляется напрямую в аппаратный SAI DMA.
**Интеграция с прошивкой STM32:** прошивка и Windows-приложение используют один и тот же интерфейс `synth_engine.h` и один и тот же `MIDI_Dispatch`, поэтому звучание, отлаженное на ПК, совпадает с прошивкой.
**Названия CC в мониторе:** в режиме `--monitor` подписи контроллеров (`Damp`, `Decay`, `Sustain`) соответствуют синтезатору `pluck`; для `epiano` смысл CC описан в [EPIANO_SYNTH.md](EPIANO_SYNTH.md).

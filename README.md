# PurrMidi
**PurrMidi** — экспериментальный автономный MIDI-синтезатор на базе STM32.
Цель проекта — создать компактный аппаратный MIDI-модуль (sound module): подключить USB MIDI-клавиатуру, генерировать звук силами микроконтроллера и выводить его через внешний аудио ЦАП. Основное направление - качественный звук фортепиано.
Проект развивается как практический embedded-аудио проект с постепенным переходом от простого прототипа к полноценному полифоническому синтезатору.

## Аппаратное обеспечение (Кратко)
* **Микроконтроллер (MCU):** WeAct STM32H743VIT6 Mini (Cortex-M7).
* **Тактирование:** HSE 25 МГц; текущая частота CPU — 480 МГц, USB — 48 МГц, Аудио — 48 кГц.
* **Аудио ЦАП (DAC):** PCM5102A (стереовыход, I2S через SAI1 Block A, 16 бит, 2 слота, кадр 32 бита).
* **MIDI-вход:** USB MIDI-клавиатура (USB OTG FS Host).
* **Дисплей:** встроенный TFT ST7735 160×80 (SPI4) — статус MIDI, активные ноты, название аккорда.
* **Карта памяти:** встроенный слот microSD (SDMMC1, 4 бита) — см. раздел «Работа с SD-картой»*.

*(Внимание: Все физические подключения и распиновка вынесены в отдельный файл `PINOUT.md`)*

## Архитектура программного обеспечения и звуковой тракт
Разработка ведётся инкрементально: каждый аппаратный блок сначала тестируется отдельно, а затем интегрируется в синтезатор. Прошивка разделяет аппаратно-зависимый код (MIDI-ввод и аудиовывод) и сам движок синтезатора. Движок не должен напрямую зависеть от API периферии STM32, что позволит разрабатывать и тестировать его независимо.

**Схема тракта прохождения сигнала:**
```text
USB MIDI-клавиатура
        │
        ▼
USB OTG FS Host
        │
        ▼
MIDI-парсер / очередь событий
        │
        ▼
Движок синтезатора
        │
        ▼
Аудиомикшер / PCM-буфер
        │
        ▼
SAI1 Block A + DMA
        │
        ▼
PCM5102A
        │
        ▼
Аудиовыход
```
**Работа с DMA и памятью:**
* Непрерывная потоковая передача аудио использует DMA (запрос `SAI1_A`, поток DMA2 Stream0 в режиме circular; кольцевой буфер 256 стерео-кадров, разделённый на две половины), чтобы освободить процессор.
* Аудиобуферы должны располагаться в памяти, доступной DMA; быстрая память DTCM для них не подходит.
* Для ядра Cortex-M7 необходимо учитывать D-cache: буферы должны располагаться в некэшируемой области MPU (или требуется ручное обслуживание кэша), с выравниванием по 32-байтовой границе.
* Сейчас D-cache выключен, а аудиобуфер лежит в отдельной секции `.dma_buffer` в AXI SRAM (0x24000000). Секции `.data`, `.bss`, куча и стек находятся в DTCM, недоступной для DMA.

## Звуковой движок
В рамках проекта утверждена следующая концепция звукового генератора:
* **Для первоначального тестирования:** использовалась простая одноголосая монофоническая синусоида (`synth.c`). Она позволила проверить базовую работу аудиотракта (корректность передачи данных через I2S/DMA и вывод звука через ЦАП PCM5102A).
* **Сейчас:** работает алгоритм Карплуса — Стронга на основе кода открытой библиотеки DaisySP (одноголосый). Эта DSP-библиотека спроектирована специально под микроконтроллеры STM32 (серия H7) и позволяет реализовать физическое моделирование струны (модуль `Pluck`) без опасной аллокации динамической памяти в аудиопотоке.

## Что уже реализовано

**Прошивка (STM32H743, `Core/`, `Engine/`, `Platform/`):**
* Тактирование: HSE 25 МГц, PLL1 → CPU 480 МГц; PLL2 настроен на точные 12.288 МГц для SAI; PLL3 даёт 48 МГц для USB.
* Аудиотракт: SAI1 Block A + DMA2 Stream0 (circular) → PCM5102A, 48 кГц, 16 бит, стерео. Буфер заполняется в прерываниях Half/Complete-transfer (`HAL_SAI_TxHalfCpltCallback` / `TxCpltCallback`).
* USB MIDI Host: собственный класс `usbh_midi` поверх USB Host Library, разбор USB-MIDI пакетов в `Platform/midi_usb`, диагностика USB (включается флагом `USB_DIAG_UART`).
* MIDI-конвейер: кольцевая очередь событий (один производитель — один потребитель) на 256 элементов (`Engine/midi/midi_queue`) и диспетчер (`midi_dispatch`): Note On/Off (включая Note On с velocity 0) и Control Change передаются в синтезатор.
* Синтезатор `pluck_synth` (DaisySP `Pluck`, алгоритм Карплуса — Стронга): реакция на velocity, затухание (release) после отпускания клавиши, педаль сустейна (CC64), управление Damp (CC1/71/74) и Decay (CC72). События Note On передаются в аудиопрерывание через lock-free SPSC FIFO. Сейчас синтезатор **одноголосый**.
* Отладочный синусоидальный тон (`synth.c`) оставлен в проекте, в `main.c` закомментирован.
* Экран ST7735 (`display.c`, SPI4): индикатор подключения MIDI, активные ноты и определение аккорда (`chord_detector`: название аккорда, обращения, септаккорды).
* Отладочный UART (USART3, 115200 8N1): `printf` перенаправлен в UART, светодиод PE3 горит, пока нажата хотя бы одна нота.
* Исправление зависания энумерации USB-устройств (порт молча отключается после reset) описано в [docs/USB_Enumeration_fix.md](docs/USB_Enumeration_fix.md).

**Windows-приложение (`platform/windows/`):** MIDI-монитор и плеер на том же коде синтезатора, выбор MIDI-порта и размера аудиобуфера, регулировка громкости, запись выхода в WAV (см. [docs/WINDOWS_BUILD.md](docs/WINDOWS_BUILD.md)).

**Тесты и CI:**
* Хостовые тесты (`tests/`): декодер MIDI, очередь и диспетчер, `pluck_synth` (рендер, частота, Note On с velocity 0, сустейн), детектор аккордов.
* GitHub Actions (`.github/workflows/host-ci.yml`): сборка и запуск тестов на Linux, сборка `purrmidi_win.exe` (MSVC) на Windows.
* CMake-пресеты: `host-tests`, `win-msvc-debug/release`, `win-mingw-release`, а также `Debug`/`Release` для прошивки.

**Пока не реализовано:** загрузка SF2, полифония, Pitch Bend, aftertouch, пресеты, кнопки и энкодер, внешняя Flash.

## Работа с SD-картой (SDMMC1)
Цель — читать с карты банки `.SF2` и другие файлы. Ниже настройки, которые нужно сделать в STM32CubeMX. Распиновка (PC8–PC12, PD2, опционально PD4) приведена в [PINOUT.md](PINOUT.md).

**Настройки в CubeMX:**
1. **Connectivity → SDMMC1:** Mode `SD 4 bits Wide bus`. Clock Edge: Rising, Clock Power Save: Disable, Hardware Flow Control: Disable. **Clock divide factor = 4** (SDMMC_CK = 192 МГц / (2·4) = 24 МГц; значение 0 даёт 96 МГц, и карта не заработает). Инициализацию на 400 кГц выполняет HAL.
2. **GPIO Settings:** скорость выводов `Very High`; подтяжки вверх на D0–D3 и CMD, на CLK без подтяжки.
3. **Clock Configuration:** источник тактирования SDMMC — PLL1Q (192 МГц, уже так настроено). PLL2 не менять: от него SAI получает 12.288 МГц.
4. **NVIC:** включить `SDMMC1 global interrupt` с приоритетом ниже, чем у аудио DMA и USB (например, 5). Отдельный канал DMA для SDMMC не нужен: используется встроенный IDMA.
5. **Card detect (по желанию):** PD4 как GPIO Input с меткой `SD_DETECT` (проверьте перемычку SB2 и полярность по схеме платы).
6. **Middleware → FATFS:** Mode `SD Card`; `USE_LFN` = Enabled with static working buffer; `MAX_SS`/`MIN_SS` = 512; `USE_FASTSEEK` = Enabled (быстрый произвольный доступ при чтении SF2); для кириллических имён — Code Page 866. Карту форматировать в FAT32 (exFAT требует включения `FS_EXFAT`).

**Важно: память для DMA.** IDMA контроллера SDMMC1 не имеет доступа к DTCM, а в этом проекте там лежат `.data`, `.bss`, куча и стек. FatFs передаёт драйверу диска не только пользовательский буфер, но и внутренние буферы объектов `FATFS` и `FIL` (по 512 байт). Поэтому:
* объекты `SDFatFS`, `SDFile` и буферы чтения нужно размещать в AXI SRAM, например атрибутом `__attribute__((section(".dma_buffer"), aligned(32)))` (секция `.dma_buffer` уже есть в `STM32H743xx_FLASH.ld`);
* либо на первом этапе отключить DMA-вариант драйвера диска («Use dma template») и читать в режиме опроса: медленнее, но работает с любой памятью.

D-cache сейчас выключен, поэтому обслуживание кэша не требуется. Если его включат, вокруг каждой DMA-транзакции потребуется Clean/Invalidate.

**Про SF2:** целиком банк с роялем не поместится в RAM (около 1 МБ в сумме), поэтому сэмплы придётся читать с карты потоком или копировать во внешнюю Flash.

Проект использует библиотеку DaisySP в качестве Git-подмодуля https://github.com/electro-smith/DaisySP

```bash
git submodule update --init --recursive
```

Для отладки и проверки работы алгоритмов синтезатора без постоянной прошивки микроконтроллера доступно автономное Windows-приложение `purrmidi_win.exe`. Оно использует тот же код синтезатора (`pluck_synth.cpp`, DaisySP Pluck), что и прошивка STM32.

Подробные инструкции по сборке и запуску приведены в документе [docs/WINDOWS_BUILD.md](docs/WINDOWS_BUILD.md).

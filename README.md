# PurrMidi

**PurrMidi** — экспериментальный автономный MIDI-синтезатор на базе STM32.

Цель проекта — создать компактный аппаратный MIDI-модуль (sound module): подключить USB MIDI-клавиатуру, генерировать звук силами микроконтроллера и выводить его через внешний аудио ЦАП. Основное направление — качественный звук фортепиано.

Проект прошёл этап базового аппаратного запуска и интеграции нескольких звуковых движков. Сейчас в нём реализованы аппаратная прошивка STM32, Windows-приложение для разработки и проверки синтезаторов, пять звуковых движков, переключение инструментов через MIDI Program Change и хостовые автоматические тесты. Проект продолжает развиваться и пока не позиционируется как законченный серийный продукт.

## Аппаратное обеспечение

* **Микроконтроллер:** WeAct STM32H743VIT6 Mini (Cortex-M7).
* **Тактирование:** HSE 25 МГц; CPU 480 МГц, USB 48 МГц, аудио 48 кГц.
* **Аудио ЦАП:** PCM5102A, стереовыход через SAI1 Block A, 16 бит, два слота, кадр 32 бита.
* **MIDI-вход:** USB MIDI-клавиатура через USB OTG FS Host.
* **Дисплей:** TFT ST7735 160×80, SPI4 — статус MIDI, активные ноты и название аккорда.
* **Карта памяти:** microSD через SDMMC1, 4-битный режим. SoundFont-банк располагается в `0:/SNDFNT.SF2`.

Физические подключения и распиновка описаны в `PINOUT.md`.

## Архитектура программного обеспечения

Проект разделяет обработку MIDI, звуковые движки и аппаратный аудиовывод. Общий интерфейс движков находится в `Engine/synth/synth_engine.h`, реализация диспетчера — в `Engine/synth/synth_engine.cpp`.

Основной путь MIDI-событий:

```text
USB MIDI-клавиатура
        │
        ▼
USB Host / MIDI-декодирование
        │
        ▼
MIDI-очередь событий
        │
        ▼
MIDI_Dispatch()
        │
        ▼
SynthEngine
        │
        ▼
Заполнение стереобуфера
        │
        ▼
SAI1 Block A + DMA
        │
        ▼
PCM5102A
        │
        ▼
Аудиовыход
```

MIDI-диспетчер обрабатывает Note On, Note Off, Control Change и Program Change. Note On с velocity `0` трактуется как Note Off. События передаются активному звуковому движку через единый интерфейс.

В аппаратной версии аудиобуфер заполняется в обработчиках завершения половины и полного блока DMA. В Windows-приложении используются тот же код звуковых движков и общий диспетчер, но аудиовывод реализован средствами платформы Windows.

### DMA и память STM32

* Аудиопередача использует SAI1 Block A и DMA2 Stream0 в режиме circular.
* Кольцевой аудиобуфер содержит 256 стереокадров и разделён на две половины.
* Аудиобуфер должен находиться в памяти, доступной DMA; DTCM для него не подходит.
* Для Cortex-M7 необходимо учитывать согласованность D-cache и DMA, а также выравнивание буферов по границе 32 байта.
* В текущей конфигурации D-cache выключен, аудиобуфер расположен в секции `.dma_buffer` в AXI SRAM по адресу `0x24000000`. Секции `.data`, `.bss`, куча и стек находятся в DTCM.

### Поведение MIDI Program Change

В обработчике MIDI используется **нулевая нумерация** значения Program Change (`data1`). Некоторые MIDI-клавиатуры и программы показывают номера программ с единицы, поэтому значение `data1 = 127` может отображаться в интерфейсе как программа №128.

| Значение `data1` | Поведение                                  |
| ---------------: | ------------------------------------------ |
|              `0` | Выбрать E-Piano                            |
|              `1` | Выбрать Pluck                              |
|              `2` | Выбрать Sine                               |
|              `3` | Выбрать Organ                              |
|              `4` | Выбрать SoundFont                          |
|          `5…126` | Циклический выбор по формуле `program % 5` |
|        **`127`** | **Переключиться на следующий инструмент**  |

Значение `127` зарезервировано как команда **Next Instrument**. Оно не проходит через обычное сопоставление номера программы по модулю. При каждом таком сообщении активный инструмент меняется на следующий в последовательности:

```text
E-Piano → Pluck → Sine → Organ → SoundFont
    ↑                                  │
    └──────────────────────────────────┘
```

Таким образом, последовательные сообщения Program Change `127` циклически перебирают все пять инструментов.

Другие правила переключения:

* Обычные номера программ `0–4` напрямую выбирают соответствующий инструмент.
* Для номеров `5–126` используется циклическое сопоставление по модулю количества движков.
* MIDI-канал Program Change не учитывается: переключение работает в режиме omni.
* При повторном выборе уже активного инструмента состояние движка не сбрасывается.
* При смене инструмента новый движок инициализируется с чистого состояния. Переключение может сопровождаться кратковременной выдачей тишины, чтобы не блокировать аудиопрерывание.
* Выбор инструмента не сохраняется между включениями. По умолчанию запускается E-Piano; значение задаётся `SYNTH_ENGINE_DEFAULT` в `Engine/synth/synth_engine.h`.
* Переключение может выводиться в UART в формате `[PC] program N -> <имя>`; Windows-приложение также выводит диагностические сообщения в консоль.

Для кнопки, назначенной на переключение следующего инструмента, следует использовать MIDI Program Change со значением `127`. Например, это позволяет использовать кнопку SUS контроллера для последовательного перебора звуков, если контроллер можно настроить на отправку такого сообщения.

### Общий интерфейс движков

Основные функции общего API:

* `SynthEngine_Init()` — запуск движка по умолчанию.
* `SynthEngine_NoteOn()` и `SynthEngine_NoteOff()` — обработка нот.
* `SynthEngine_ControlChange()` — передача MIDI Control Change.
* `SynthEngine_ProgramChange()` — выбор инструмента по номеру программы.
* `SynthEngine_Select()` — явный выбор движка по идентификатору.
* `SynthEngine_GetCurrent()` — получение текущего инструмента.
* `SynthEngine_FillStereoBuffer()` — заполнение стереобуфера.

Состояние выбора не сохраняется в энергонезависимой памяти. Вызовы управления выполняются из основного цикла или MIDI-контекста, а заполнение аудиобуфера — из аудиопрерывания на STM32 либо аудиопотока на ПК.

## Что уже реализовано

### Прошивка STM32H743

* Тактирование STM32H743VIT6: HSE 25 МГц, CPU 480 МГц, USB 48 МГц и тактирование аудио.
* Вывод стереозвука через SAI1 Block A, DMA2 Stream0 и PCM5102A: 48 кГц, 16 бит.
* USB MIDI Host с собственным классом `usbh_midi` поверх USB Host Library.
* Разбор USB-MIDI пакетов и диагностика USB, включаемая флагом `USB_DIAG_UART`.
* MIDI-очередь на 256 событий с моделью SPSC (один производитель — один потребитель) и диспетчер MIDI-событий.
* Обработка Note On, Note Off, Control Change и Program Change.
* Единый диспетчер пяти звуковых движков.
* E-Piano с FM-синтезом и полифонией до 8 голосов.
* Pluck на базе DaisySP с обработкой velocity, release, педали сустейна CC64 и параметров тембра.
* Organ на базе `bfreeOrgan2`: полифония, девять drawbars (CC20–28), хорус и управление огибающей.
* SoundFont2 на базе TinySoundFont с 64-КБ RAM-кэшем и потоковым чтением с microSD. Для воспроизведения необходим корректно настроенный накопитель и файл `0:/SNDFNT.SF2`.
* Тестовый синусоидальный движок для диагностики аудиотракта.
* TFT ST7735: индикация подключения MIDI, активных нот и определение аккордов.
* Отладочный UART (USART3, 115200 8N1) и светодиод PE3, сигнализирующий о наличии нажатых нот.
* Исправление зависания энумерации USB-устройств описано в `docs/USB_Enumeration_fix.md`.

### Windows-приложение

В каталоге `platform/windows/` находится приложение для проверки синтезаторов на ПК. Оно использует общий код движков и поддерживает MIDI-мониторинг, выбор MIDI-порта, настройку размера аудиобуфера, регулировку громкости и запись аудиовыхода в WAV.

Инструкции по сборке находятся в `docs/WINDOWS_BUILD.md`.

### Тесты и непрерывная интеграция

В `tests/` находятся хостовые тесты MIDI-декодера, очереди событий, диспетчера, звуковых движков, переключения инструментов, SoundFont-кэша и детектора аккордов.

GitHub Actions (`.github/workflows/host-ci.yml`) выполняет:

* сборку и запуск хостовых тестов в Linux;
* сборку Windows-приложения `purrmidi_win.exe` с помощью MSVC.

В репозитории есть CMake-пресеты для прошивки (`Debug`, `Release`), хостовых тестов (`host-tests`) и Windows-сборок (`win-msvc-debug`, `win-msvc-release`, `win-mingw-release`).

## Работа с SD-картой (SDMMC1)

Файл банка SoundFont должен находиться в корне microSD-карты по пути `0:/SNDFNT.SF2`.

Основные настройки CubeMX:

1. **Connectivity → SDMMC1:** режим `SD 4 bits Wide bus`, Clock Edge — Rising, Clock Power Save — Disable, Hardware Flow Control — Disable.
2. **Clock divide factor:** `4` при источнике SDMMC 192 МГц, что даёт частоту SDMMC_CK 24 МГц по формуле `192 МГц / (2 × 4)`.
3. **GPIO:** скорость выводов `Very High`; подтяжки вверх на D0–D3 и CMD, без подтяжки на CLK.
4. **Clock Configuration:** источник тактирования SDMMC — PLL1Q (192 МГц).
5. **Middleware → FATFS:** режим `SD Card`, `USE_LFN` — Enabled with static working buffer, `MAX_SS`/`MIN_SS` — 512, `USE_FASTSEEK` — Enabled.

Карту следует форматировать в FAT32. Работа SoundFont-движка зависит от наличия и корректности файла банка и конфигурации SDMMC/FatFs.

## Сборка

### Инициализация подмодулей

```bash
git submodule update --init --recursive
```

### Прошивка STM32

```bash
cmake --preset Debug
cmake --build --preset Debug
```

Для релизной сборки:

```bash
cmake --preset Release
cmake --build --preset Release
```

### Хостовые тесты

```bash
cmake --preset host-tests
cmake --build --preset host-tests
ctest --test-dir build/host-tests --output-on-failure
```

### Windows-версия

В Windows с установленным CMake и компилятором MSVC:

```bash
cmake --preset win-msvc-release
cmake --build --preset win-msvc-release
```

Инструкции и дополнительные сведения: `docs/WINDOWS_BUILD.md`.

# PurrMidi

**PurrMidi** — экспериментальный автономный MIDI-синтезатор на базе STM32.

Цель проекта — создать компактный аппаратный MIDI-модуль (sound module): подключить USB MIDI-клавиатуру, генерировать звук силами микроконтроллера и выводить его через внешний аудио ЦАП. Основное направление — качественный звук фортепиано.

Проект прошёл этап базового аппаратного запуска и интеграции нескольких звуковых движков. Сейчас в нём реализованы аппаратная прошивка STM32, Windows-приложение для разработки и проверки синтезаторов, восемь звуковых движков, переключение инструментов через MIDI Program Change и хостовые автоматические тесты. Проект продолжает развиваться и пока не позиционируется как законченный серийный продукт.

## Аппаратное обеспечение

* **Микроконтроллер:** WeAct STM32H743VIT6 Mini (Cortex-M7).
* **Тактирование:** HSE 25 МГц; CPU 480 МГц, USB 48 МГц, аудио 48 кГц.
* **Аудио ЦАП:** PCM5102A, стереовыход через SAI1 Block A, 16 бит, два слота, кадр 32 бита.
* **MIDI-вход:** USB MIDI-клавиатура через USB OTG FS Host.
* **Кнопка управления:** User Key K1 (PC13) на плате микроконтроллера для переключения инструмента.
* **Дисплей:** TFT ST7735 160×80, SPI4 — статус MIDI, активные ноты, название аккорда и выбранный инструмент.
* **Внешняя флеш-память:** Winbond W25Q64 (8 МБ), QUADSPI Bank1. Используется в режиме прямого адресации Memory-Mapped (XIP) для хранения и мгновенного исполнения/чтения сэмплов SoundFont.
* **Карта памяти:** microSD через SDMMC1, 4-битный режим (FAT32). Используется **только при запуске** и **только для чтения**: для автоматической записи/обновления SoundFont-банка `0:/SNDFNT.SF2` во внешнюю QSPI Flash. Во время игры SD-карта не нужна и не используется.

Физические подключения и распиновка описаны в `PINOUT.md`.

## Архитектура программного обеспечения

Проект разделяет обработку MIDI, звуковые движки и аппаратный аудиовывод. Общий интерфейс движков находится в `Engine/synth/synth_engine.h`, реализация диспетчера — в `Engine/synth/synth_engine.cpp`.

Основной путь MIDI-событий:

```text
USB MIDI-клавиатура
        │
        ▼
USB Host / MIDI-декодирование
        │
        ▼
MIDI-очередь событий
        │
        ▼
MIDI_Dispatch()
        │
        ▼
SynthEngine
        │
        ▼
Заполнение стереобуфера
        │
        ▼
SAI1 Block A + DMA
        │
        ▼
PCM5102A
        │
        ▼
Аудиовыход
```

Разбор 4-байтовых USB-MIDI пакетов вынесен в чистую функцию `UsbMidi_PacketToEvent()` (`Engine/midi/usb_midi_packet.c`, покрыта хостовым тестом): она пропускает только сообщения голосового канала, а SysEx, MIDI Clock, Active Sensing и прочие системные сообщения отбрасывает; байты данных маскируются до 7 бит.

MIDI-диспетчер обрабатывает Note On, Note Off, Control Change, Program Change, Pitch Bend, Channel Pressure и Polyphonic Key Pressure. Pitch Bend сейчас реально звучит в E-Piano (±2 полутона) и SoundFont (по RPN 0, по умолчанию ±2); остальные движки его игнорируют. Aftertouch маршрутизируется к движку, но пока ни одним не используется. Если USB-клавиатуру отключили, активный движок сбрасывается (`SynthEngine_Panic()`), чтобы не оставалось «залипших» нот. Note On с velocity `0` трактуется как Note Off. События передаются активному звуковому движку через единый интерфейс.

В аппаратной версии аудиобуфер заполняется в обработчиках завершения половины и полного блока DMA. В Windows-приложении используются тот же код звуковых движков и общий диспетчер, но аудиовывод реализован средствами платформы Windows.

### DMA, D-Cache и память STM32

* Аудиопередача использует SAI1 Block A и DMA2 Stream0 в режиме circular.
* Кольцевой аудиобуфер содержит 256 стереокадров и разделён на две половины.
* Рендер звука выполняется не в прерывании DMA, а в **PendSV** с самым низким приоритетом: прерывание DMA2 Stream0 (приоритет 0) только отмечает, какая половина буфера освободилась (`Engine/audio/audio_halves.c`), и запускает PendSV; рендер блока (до 2,67 мс) вытесняется USB (0), SAI (1), SDMMC (5) и SysTick (14). Если рендер не успевает, пропущенный срок учитывается (`late=` в строке `[AUDIO]`, индикация на дисплее), а устаревшая половина заливается тишиной вместо повтора старого звука. Приоритеты заданы в CubeMX (`PendSV` — 15, `SysTick` — 14).
* **Карта SRAM.** Каждая область отвечает за своё:
  * **DTCM** (128 КБ): `.data`, `.bss`, стек (недоступна DMA);
  * **D2 SRAM** (288 КБ, `0x30000000`): только DMA-буферы — секция `.dma_buffer` (кольцо SAI1, bounce-буфер SD, буфер загрузчика SF2), около 17 КБ. MPU: Normal Non-cacheable, DMA и CPU видят одни и те же данные без операций с кэшем;
  * **AXI SRAM** (512 КБ, `0x24000000`): **арена голосов** `.synth_arena` (144 КБ, общая для всех движков) и **куча malloc** `.axi_heap` (320 КБ: метаданные TinySoundFont, USB). MPU: Normal Write-back + write-allocate, кэшируется D-cache; DMA сюда не работает. Занято около 90%.
* **Арена голосов** (`Engine/synth/synth_arena.h`). Одновременно звучит один движок, поэтому голоса Dulcimer (138 КБ), Pluck (67 КБ), Sax (66 КБ), Flute (50 КБ) и Lead (2 КБ) делят одну область размером с самый большой набор вместо 320 КБ раздельной памяти. Движок создаёт голоса в арене в своём `Init()` (`SynthArena_NewArray`, явные конструкторы), а движок, у которого арену забрал другой, молчит. Увеличить арену нужно, только если новый движок не помещается: `static_assert` и `ASSERT` линкера подскажут (`SYNTH_ARENA_BYTES`).
* **Общая инфраструктура движков** (`Engine/synth/synth_common.h`): очередь событий с резервом под Note Off и протоколом аварийного восстановления (`synth::NoteInput`), мягкий ограничитель `synth::SoftLimit`, таблица частот `synth::MidiFreq`. Раньше эти ~150 строк были скопированы в пять движков; звук после выноса совпадает бит-в-бит (`test_engine_golden`).
* Для быстрой и эффективной работы QSPI Flash в режиме Memory-Mapped (XIP) включён **D-Cache** для MPU-региона `0x90000000...0x907FFFFF` (8 МБ, read-only, write-through). Это позволяет подтягивать данные сэмплов TinySoundFont 32-байтными строками кэша без задержек.
* DMA-буферы лежат только в D2 SRAM (Normal Non-cacheable), а AXI SRAM кэшируется write-back: линии задержки физических моделей (Flute, Sax, Dulcimer, Pluck) читаются последовательно и хорошо ложатся в 16-КБ D-cache. Драйвер SD разрешает прямую DMA-передачу только в `.dma_buffer`, всё остальное идёт через bounce-буфер, поэтому когерентность кэша не нарушается. **Любой новый DMA-буфер обязан лежать в `.dma_buffer`.**
* Секции `.dma_buffer`, `.synth_arena` и `.axi_heap` (NOLOAD) не обнуляются startup-кодом и не получают начальных значений (объекты с инициализаторами в них терялись бы), а AXI SRAM защищена ECC (слово 64 бита): неполная запись в неинициализированное слово может вызвать ECC-ошибку. Поэтому `Core/Src/ram_init.c` до запуска C++-конструкторов (через `.preinit_array`) записывает нули 64-битными словами (`STRD`) во всю AXI SRAM и всю D2 SRAM (границы — символы линкер-скрипта), а объекты в арене создаются явно. Startup-файл CubeMX менять не нужно.
* **Контракт XIP.** Любая индексная операция QSPI (чтение, стирание, запись) выключает Memory-Mapped режим и закрывает MPU-окно `0x90000000`; чтение банка в этот момент вызвало бы MemManage. Поэтому драйвер сбрасывает признак `QSPIFlash_IsMapped()` до закрытия окна и устанавливает его после открытия, а синтезатор SoundFont перед каждым блоком проверяет `SF2Loader_BankReadable()` и при закрытом окне отдаёт тишину. Загрузчик/обновление банка выполняется только при старте.

### Поведение MIDI Program Change

В обработчике MIDI используется **нулевая нумерация** значения Program Change (`data1`). Некоторые MIDI-клавиатуры и программы показывают номера программ с единицы, поэтому значение `data1 = 127` может отображаться в интерфейсе как программа №128.

| Значение `data1` | Поведение                                  |
| ---------------: | ------------------------------------------ |
|              `0` | Выбрать E-Piano                            |
|              `1` | Выбрать Pluck                              |
|              `2` | Выбрать Lead                               |
|              `3` | Выбрать Organ                              |
|              `4` | Выбрать SoundFont                          |
|          `5…7` | Выбрать Dulcimer / Flute / Saxophone       |
|         `8…126` | Циклический выбор по формуле `program % 8` |
|        **`127`** | **Переключиться на следующий инструмент**  |

Значение `127` зарезервировано как команда **Next Instrument**. Оно не проходит через обычное сопоставление номера программы по модулю. При каждом таком сообщении активный инструмент меняется на следующий в последовательности:

```text
E-Piano → Pluck → Lead → Organ → SoundFont → Dulcimer → Flute → Saxophone
    ↑                                                              │
    └──────────────────────────────────────────────────────────────┘
```

Таким образом, последовательные сообщения Program Change `127` циклически перебирают все восемь инструментов. Если банк SoundFont недоступен, он автоматически пропускается в цикле.

Другие правила переключения:

* Обычные номера программ `0–7` напрямую выбирают соответствующий инструмент.
* Для номеров `8–126` используется циклическое сопоставление по модулю количества движков.
* MIDI-канал Program Change не учитывается: переключение работает в режиме omni.
* При повторном выборе уже активного инструмента состояние движка не сбрасывается.
* При смене инструмента новый движок инициализируется с чистого состояния. Переключение может сопровождаться кратковременной выдачей тишины, чтобы не блокировать аудиопрерывание.
* Выбор инструмента не сохраняется между включениями. По умолчанию запускается E-Piano; значение задаётся `SYNTH_ENGINE_DEFAULT` в `Engine/synth/synth_engine.h`.
* Переключение может выводиться в UART в формате `[PC] program N -> <имя>`; Windows-приложение также выводит диагностические сообщения в консоль.

Для кнопки, назначенной на переключение следующего инструмента, следует использовать MIDI Program Change со значением `127`. Например, это позволяет использовать кнопку SUS контроллера для последовательного перебора звуков, если контроллер можно настроить на отправку такого сообщения.

Кроме того, циклический перебор доступных инструментов можно выполнять встроенной кнопкой **User Key K1 (PC13)** на плате. Одно нажатие K1 приводит к переключению на следующий доступный инструмент (как MIDI Program Change `127`), использует ту же логику пропуска недоступных движков, обрабатывается в основном цикле с неблокирующим программным debounce и обновляет отображение инструмента на дисплее.

### Общая громкость (MIDI CC7)

Громкость всего синтезатора регулируется с MIDI-клавиатуры сообщением Control Change **CC7** (Channel Volume) — его обычно шлют ползунок или ручка громкости. Канал не учитывается.

У PCM5102A нет аппаратной регулировки громкости (у него нет ни I2C, ни SPI; из управляющих выводов только FLT, DEMP, XSMT и FMT), поэтому громкость меняется программно: `SynthEngine_FillStereoBuffer()` умножает выходные отсчёты активного движка на коэффициент. Это работает одинаково для всех восьми движков и не сбрасывается при смене инструмента.

* Кривая квадратичная: `127` → 1.0 (без ослабления), `64` → ≈0.25 (−12 дБ), `0` → тишина.
* Коэффициент меняется плавно внутри блока, поэтому щелчков при вращении ручки нет.
* После включения питания громкость равна `127` (как до появления регулировки).
* CC7 перехватывается в `SynthEngine_ControlChange()` и в движки не передаётся (иначе громкость применялась бы дважды).
* Номер контроллера и стартовый уровень переопределяются макросами `SYNTH_MASTER_VOLUME_CC` и `SYNTH_MASTER_VOLUME_DEFAULT` (`Engine/synth/synth_engine.h`).
* Программный доступ: `SynthEngine_SetMasterVolume()` и `SynthEngine_GetMasterVolume()`.

### Общий интерфейс движков

Основные функции общего API:

* `SynthEngine_Init()` — запуск движка по умолчанию.
* `SynthEngine_NoteOn()` и `SynthEngine_NoteOff()` — обработка нот.
* `SynthEngine_ControlChange()` — передача MIDI Control Change.
* `SynthEngine_ProgramChange()` — выбор инструмента по номеру программы.
* `SynthEngine_Select()` — явный выбор движка по идентификатору.
* `SynthEngine_GetCurrent()` — получение текущего инструмента.
* `SynthEngine_FillStereoBuffer()` — заполнение стереобуфера.

Состояние выбора не сохраняется в энергонезависимой памяти. Вызовы управления выполняются из основного цикла или MIDI-контекста, а заполнение аудиобуфера — из аудиопрерывания на STM32 либо аудиопотока на ПК.

## Что уже реализовано

### Прошивка STM32H743

* Тактирование STM32H743VIT6: HSE 25 МГц, CPU 480 МГц, USB 48 МГц и тактирование аудио.
* Вывод стереозвука через SAI1 Block A, DMA2 Stream0 и PCM5102A: 48 кГц, 16 бит.
* USB MIDI Host с собственным классом `usbh_midi` поверх USB Host Library.
* Разбор USB-MIDI пакетов (`Engine/midi/usb_midi_packet.c`) с отсевом SysEx/Clock/Active Sensing и маскированием данных.
* MIDI-очередь на 256 событий с моделью SPSC (один производитель — один потребитель) и диспетчер MIDI-событий.
* Обработка Note On, Note Off, Control Change и Program Change.
* Единый диспетчер восьми звуковых движков.
* E-Piano с FM-синтезом и полифонией до 8 голосов.
* Pluck на базе DaisySP с обработкой velocity, release, педали сустейна CC64 и параметров тембра.
* Organ на базе `bfreeOrgan2`: полифония, девять drawbars (CC20–28), хорус и управление огибающей.
* SoundFont2 на базе TinySoundFont с хранением банка во внешней QSPI Flash (8 МБ, режим XIP) и автоматическим прошиванием/обновлением с microSD-карты (`0:/SNDFNT.SF2`) при запуске. Банк хранится только во флеше; проигрывания напрямую с SD-карты нет.
* Настройка D-Cache: XIP-окно QSPI (read-only, write-through), AXI SRAM (write-back) для данных движков и кучи; DMA-буферы вынесены в non-cacheable D2 SRAM.
* Тестовый синусоидальный движок для диагностики аудиотракта.
* TFT ST7735: индикация подключения MIDI, активных нот, отображение прогресса загрузки/прошивки SoundFont и определение аккордов.
* Отладочный UART (USART3, 115200 8N1) и светодиод PE3, сигнализирующий о наличии нажатых нот.
* Исправление зависания энумерации USB-устройств описано в `docs/USB_Enumeration_fix.md`.
* Сброс звука при отключении USB-клавиатуры (нет «залипших» нот).
* Автоматический перезапуск после аппаратного сбоя (HardFault/MemManage/BusFault/UsageFault/NMI): отчёт о сбое уходит в UART, затем `NVIC_SystemReset()`. Для отладки по SWD соберите с `-DPURRMIDI_FAULT_HALT=1`, тогда после отчёта процессор останавливается.
* Контроль ошибок SAI (underrun/overrun) через прерывание SAI1.
* **Сторожевой таймер IWDG1** (`Core/Src/watchdog.c`): при загрузке таймаут ~8 с (обновление банка во флеше «кормит» таймер на каждом шаге), в работе ~1,5 с. Основной цикл «кормит» таймер только пока звук реально идёт (растёт счётчик блоков, обработанных PendSV), поэтому сбрасывается и зависший `main`, и остановившийся звук. Причина последнего сброса (IWDG, программный, питание...) печатается в UART строкой `[RESET] cause: ...`. Таймер замораживается при остановке ядра отладчиком. Модуль работает с регистрами и не зависит от HAL-модуля IWDG.
* Обнуление AXI SRAM и D2 SRAM 64-битными записями до конструкторов C++ (защита от ECC-ошибок на холодном старте).
* Рендер звука в PendSV (низкий приоритет), а не в прерывании DMA: USB и системный тик не блокируются на время расчёта блока.
* Общая арена памяти голосов и общий компонент `synth_common.h` для движков: RAM_D2 освобождена с 86% до 6%.

## Работа с SD-картой (SDMMC1) и QSPI Flash

SD-карта нужна **только для обновления банка**. Банк SoundFont хранится во внешней QSPI Flash и читается синтезатором оттуда (XIP); с SD-карты звук не воспроизводится. Чтобы обновить банк, положите новый файл в корень microSD-карты по пути `0:/SNDFNT.SF2`, вставьте карту и включите прибор. Если карты нет, прибор запускается с банком, который уже записан во флеш. Карту можно вынимать после старта.

При старте микроконтроллера загрузчик проверяет заголовок во внешней QSPI Flash W25Q64:
- Если заголовок совпадает с файлом на картe (размер, штамп времени, CRC32), старт происходит мгновенно, и синтезатор читает сэмплы напрямую из флеш-памяти в режиме XIP.
- Если файла на карте нет, но во флеш-памяти закоммичен валидный банк, синтезатор запускается сразу из флеш-памяти.
- Если банк на карте новый или изменён, загрузчик автоматически стирает и переписывает QSPI Flash (30–60 секунд, прогресс виден на дисплее и в UART).

Основные настройки CubeMX для SDMMC1:

1. **Connectivity → SDMMC1:** режим `SD 4 bits Wide bus`, Clock Edge — Rising, Clock Power Save — Disable, Hardware Flow Control — Disable.
2. **Clock divide factor:** `4` при источнике SDMMC 192 МГц, что даёт частоту SDMMC_CK 24 МГц по формуле `192 МГц / (2 × 4)`.
3. **GPIO:** скорость выводов `Very High`; подтяжки вверх на D0–D3 и CMD, без подтяжки на CLK.
4. **Clock Configuration:** источник тактирования SDMMC — PLL1Q (192 МГц).
5. **Middleware → FATFS:** режим `User-defined` (диск-драйвер — `Core/Src/sd_storage.c`, только чтение; вызовы `MX_SDMMC1_SD_Init` и `MX_FATFS_Init` в CubeMX отключены), `USE_LFN` — Enabled with static working buffer, `MAX_SS`/`MIN_SS` — 512, `USE_FASTSEEK` — Enabled, **`FS_READONLY` — 1 (Read only)**, **`FS_LOCK` — 0** (при `FS_READONLY = 1` блокировки файлов должны быть отключены), `USE_MKFS` — 0.

> Почему не режим «SD Card» в CubeMX: сгенерированная инициализация SDMMC1 при отсутствии карты вызывает `Error_Handler()` и вешает прибор, а теперь карта вставлена только на время обновления. Кроме того, IDMA SDMMC1 не видит DTCM (там `.bss` и буферы FatFs), и сгенерированному драйверу нужны ручные обходы; в `sd_storage.c` они уже есть (bounce-буфер, проверка выравнивания и кэша).

Карту следует форматировать в FAT32.

### Диагностика: SD не монтируется / файл не открывается
При сбое в UART выводятся строки `[SD] ...` и `[SF2] ...`, по ним видно, на каком этапе остановилось:

| Строка в логе | Что означает |
|---|---|
| `SD mount failed: INIT`, `hsd.ErrorCode=0x...` | `HAL_SD_Init` не смог поднять карту: контакт, питание, тактирование, несовместимая карта. Код расшифровывается по маске `HAL_SD_ERROR_*`. |
| `SD mount failed: LINK` | `FATFS_LinkDriver` не удался: в проекте остался вызов `MX_FATFS_Init` или `_VOLUMES` ≠ 1. |
| `SD mount failed: MOUNT`, `f_mount=13` | Карта читается, но FatFs не нашёл файловую систему (`FR_NO_FILESYSTEM`). Проверьте разметку и формат. |
| `SD mount failed: MOUNT`, `f_mount=1`, `first read failure: stage=...` | `FR_DISK_ERR`: чтение сектора не удалось. `stage=1` - карта не вернулась в состояние TRANSFER, `2` - `HAL_SD_ReadBlocks_DMA` отказал, `3` - таймаут/ошибка DMA; рядом печатаются `hsd.ErrorCode` и состояние карты. |
| `f_open(...) failed: FRESULT=4` | Файла с таким именем в корне нет. Следом печатается список корня `[SD] root directory`, там видны реальные имена (частый случай: Windows скрыл расширение, и файл называется `SNDFNT.SF2.sf2`). |

Датчик наличия карты (`SD_DETECT`, PD4) не используется: карта определяется самой инициализацией `HAL_SD_Init`.

Подробности работы QSPI Flash XIP и конфигурации сэмплирования: `docs/SOUNDFONT_QSPI_SYNTH.md`.

## Сборка

### Инициализация подмодулей

```bash
git clone --recursive https://github.com/purrrock/purrmidi
# или, если репозиторий уже склонирован:
git submodule update --init --recursive
```

Флаг `--recursive` обязателен: `eurorack` содержит вложенный подмодуль `stmlib`, а `DaisySP` — `DaisySP-LGPL`. Без них CMake завершится ошибкой о ненайденных исходниках.

### Прошивка STM32

```bash
cmake --preset Debug
cmake --build --preset Debug
```

Для релизной сборки:

```bash
cmake --preset Release
cmake --build --preset Release
```

### Хостовые тесты

```bash
cmake --preset host-tests
cmake --build --preset host-tests
ctest --test-dir build/host-tests --output-on-failure
```

### Windows-версия

В Windows с установленным CMake и компилятором MSVC:

```bash
cmake --preset win-msvc-release
cmake --build --preset win-msvc-release
```

Инструкции и дополнительные сведения: `docs/WINDOWS_BUILD.md`.
